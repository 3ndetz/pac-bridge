# Обновление PAC Bridge на Windows

Для машины, на которой уже есть собственный HAPI hub и настроен PAC Bridge.

**Текущее состояние:** автоматическое обновление рабочего профиля ещё не проверено полностью. Восстановление после прерванной установки, защита от подмены путей и одновременных изменений остаются открытыми. Не запускайте установку или активацию новой версии на рабочем профиле, пока эти проверки не завершены. Состояние проверок: [инструкция установки](windows-setup.md) и [чек-лист надёжности](../RELIABILITY-CHECKLIST.md).

## Достаточно ли `git pull`?

Нет. `git pull` обновляет файлы только в папке исходников. Установленный провайдер использует отдельную копию в профиле HAPI, в каталоге `pac-bridge/provider-versions/<хеш коммита>`, и выбранную версию в `provider-current.json`. Пока новая версия отдельно не установлена и не выбрана, работающий мост не обновится.

Исходники можно обновить в постоянном Git checkout, не меняя профиль HAPI:

```powershell
cd C:\Path\To\pac-bridge
git status -sb
git fetch origin
git pull --rebase
git rev-parse HEAD
```

Перед `pull` проверьте текущую ветку и её удалённую ветку. При незакоммиченных изменениях или конфликте сохраните работу и разберите состояние; не удаляйте файлы и не делайте принудительный сброс. Запишите полученный хеш. Обновления из `main` доступны только после слияния туда; незавершённая ветка разработки не является автоматически выпущенной версией.

## Когда обновление установщика будет проверено

Из чистого checkout под Windows-пользователем, которому принадлежит существующий runner, используйте путь к **его** постоянному комплекту ServerMallAgents:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows\Install-ProviderMode.ps1 `
  -KitPath C:\Tools\ServerMallAgents -Activate -NamedProviders
```

Скрипт копирует отслеживаемые исходники выбранного коммита, устанавливает зафиксированные зависимости и выбирает эту версию провайдера. Путь к комплекту в примере замените своим. Без `-Activate` он только подготавливает версию и не выбирает её. Дополнительный `-LegacyMigration` нельзя включать автоматически: он зависит от уже установленной конфигурации и требует отдельной проверки.

Скрипт не перезапускает runner и не переносит работающие процессы чатов. Новые процессы с wrapper, поддерживающим выбор версии, могут использовать её после активации; старый wrapper может требовать согласованного перезапуска или отдельной миграции. Не запускайте миграцию live-dispatch по предположению. Текущие сессии и профиль HAPI сохраняйте; не копируйте чужой профиль или токен.

После разрешённого обновления проверьте выбранный хеш в `provider-current.json`, наличие моделей PAC в новом чате и реальный ответ в разрешённом тестовом каталоге. Отдельно проверьте продолжение существующей сессии и другие нужные возможности. Не считать один `git pull`, наличие модели или успешный запуск установщика доказательством полноценного обновления.

При ошибке сохраните состояние профиля, каталог версий и сообщения об ошибке для разбора; не повторяйте установку вслепую и не удаляйте блокировки, staging или резервные копии. Откат требует проверки конкретного установленного wrapper и состояния профиля; автоматический безопасный откат пока не подтверждён.
